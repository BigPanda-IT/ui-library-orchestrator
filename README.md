# UI Library Orchestrator

Инструменты на TypeScript для индексации React-компонентов и управления
выполнением задач через CLI. Проект включает индексатор публичного API
и оркестратор с файловым хранилищем состояния и событий.

Оркестратор работает с демонстрационным исполнителем: для любого запроса
возвращается заранее подготовленный пример с `Button`. Подключение LLM,
поиск по индексу и MCP-интеграция не реализованы.

## Индексатор компонентов

Индексатор анализирует публичный экспорт `Button` из `src/ui/index.ts`
через TypeScript Compiler API. TypeChecker раскрывает типы и унаследованные
свойства `ButtonProps`; AST функции компонента используется для извлечения
значений по умолчанию из деструктуризации параметров.

Результат сохраняется в `component-index.json` и содержит:

- имя и версию пакета, идентификатор компонента и выражение импорта;
- сигнатуру компонента, props, типы, обязательность и значения по умолчанию;
- описания JSDoc и отметки `deprecated`;
- правила использования, ключевые слова и примеры из `docs/Button.docs.json`;
- ссылки на исходные файлы.

Индекс формируется из исходного кода и отдельного файла документации.
Ошибки типов останавливают генерацию. Генерируемый файл исключён из Git.

## Оркестратор

Оркестратор принимает текст задачи, присваивает запуску UUID и вызывает
исполнителя через интерфейс `Executor`. Управление запуском, выполнение
задачи и запись результатов разделены на отдельные модули.

Успешный запуск проходит состояния `queued → running → completed`.
Ошибка исполнителя переводит запуск в `failed` с сохранением причины.
CLI проверяет входные аргументы, выводит результат и возвращает ненулевой
код завершения при ошибке.

Для каждого запуска сохраняются два файла:

| Файл | Содержимое |
|---|---|
| `runs/<runId>/run.json` | Исходная задача, состояние, временные отметки и результат либо ошибка |
| `runs/<runId>/events.jsonl` | События выполнения с идентификатором запуска, типом, временем и сообщением |

Индексатор и оркестратор запускаются независимо. Текущий `mockExecutor`
не читает индекс и возвращает фиксированный ответ. Статус `completed`
подтверждает завершение исполнителя; проверки JSX-примера имеют статус `not_run`.

## Технологии

TypeScript, Node.js, TypeScript Compiler API, React/TSX, встроенный тестовый
раннер Node.js. Компонент `Button` используется как исходный материал
для индексатора; браузерное приложение в проект не входит.

## Запуск

Проверено на Node.js 20.20.0 и npm 10.8.2.

Установка зависимостей:

```bash
npm ci
```

Генерация индекса компонентов:

```bash
npm run extract
```

Результат записывается в `component-index.json` в корне проекта.

Запуск оркестратора:

```bash
npm run orchestrate -- "Подбери кнопку для сохранения. Покажи загрузку и пример"
```

Команда автоматически собирает TypeScript и запускает CLI. Текст задачи
передаётся одним аргументом в кавычках. API-ключ не требуется.

## Структура проекта

```text
src/
  ui/                      # Button, типы props и публичные экспорты
  orchestrator/            # CLI, управление запуском, исполнитель и хранилище
scripts/
  extract-component-props.ts
tests/
  orchestrator.test.cjs
docs/
  Button.docs.json         # Правила использования и примеры компонента
  architecture.md          # Устройство оркестратора
  requirements.md          # Требования и контрольные сценарии
```

## Проверки

```bash
npm run check
npm run test:orchestrator
```

Тесты проверяют сохранение результатов, последовательность событий,
изоляцию запусков, ошибки исполнителя и хранилища, пустой ввод и поведение CLI.

## Ограничения

- Индексатор поддерживает именованный экспорт `Button` как function declaration.
- Не поддерживаются arrow-компоненты, `memo`, `forwardRef`, вычисляемые
  значения по умолчанию и инкрементальное обновление индекса.
- Оркестратор не анализирует содержание задачи и не проверяет сгенерированный JSX.
- Повторные попытки, таймауты и восстановление прерванных запусков не реализованы.
- Состояние и журнал записываются отдельно, без общей транзакции.
