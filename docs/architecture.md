# Архитектура оркестратора

## Назначение

Программа принимает задачу, создаёт запуск (`run`), вызывает исполнителя,
сохраняет результат и события. Исполнитель `mockExecutor` возвращает
фиксированный демонстрационный ответ с компонентом `Button`.
После установки зависимостей приложение работает локально без API-ключа.

Статус `completed` фиксирует успешное завершение исполнителя и сохранение результата.
В демонстрационном режиме содержание задачи не анализируется. Контрольные запросы
S1–S5 из [требований](requirements.md) не реализованы;
проверки примера имеют статус `not_run`.

## Запуск

В терминале из корня проекта, при установленных зависимостях:

```bash
npm run orchestrate -- "Подбери кнопку для сохранения. Покажи загрузку и пример"
```

Установка зависимостей выполняется командой `npm ci`.
Скрипт `preorchestrate` собирает проект перед запуском скомпилированного CLI.
`--` отделяет аргументы npm от аргументов приложения.
Кавычки передают весь запрос как один аргумент. Пустой запрос и лишние
аргументы отклоняются с кодом завершения 1, без создания запуска.

Справка:

```bash
npm run orchestrate -- --help
```

## Порядок выполнения

```text
CLI: прочитать и проверить ввод
  ↓
runTask: создать runId, сохранить queued
  ↓
runTask: сохранить running
  ↓
mockExecutor: вернуть подготовленный результат
  ↓
runTask: сохранить completed и результат
  ↓
CLI: показать результат и пути к файлам
```

При ошибке исполнителя состояние переходит из `running` в `failed`.
Причина сохраняется в состоянии и журнале; CLI возвращает код 1.
Ошибки файловой системы доходят до CLI: он сообщает об ошибке сохранения
и возвращает код 1. Когда диск недоступен, гарантировать запись `failed` нельзя.

## Модули

| Файл | Ответственность |
|---|---|
| `src/orchestrator/types.ts` | Типы запуска, результата, события и исполнителя |
| `src/orchestrator/cli.ts` | Терминальный ввод, вывод и код завершения |
| `src/orchestrator/run-task.ts` | Порядок действий и смена статусов |
| `src/orchestrator/mock-executor.ts` | Подготовленный демонстрационный ответ |
| `src/orchestrator/storage.ts` | Запись состояния и добавление событий |
| `tests/orchestrator.test.cjs` | Проверки успешного и ошибочного поведения |

`Executor` — функция, которая принимает текст задачи и асинхронно возвращает
результат. Исполнитель передаётся в `runTask` через параметр `executor`;
по умолчанию используется `mockExecutor`. Поле `mode: "mock"` обозначает
демонстрационный режим выполнения.

## Состояние и события

Каждый запуск получает UUID и отдельную папку в корне проекта:

```text
runs/<runId>/
  run.json       — последнее сохранённое состояние
  events.jsonl   — последовательность событий
```

`run.json` хранит последнее сохранённое состояние запуска:
исходную задачу, идентификатор, временные отметки, статус
и результат либо ошибку. Файл обновляется при смене статуса через
временный файл и переименование.

`events.jsonl` хранит журнал выполнения.
Каждая строка — самостоятельный JSON-объект с `runId`, временем,
типом события и сообщением. При успехе записываются:

```text
run.created
run.started
executor.started
executor.completed
run.completed
```

Время хранится в ISO-формате UTC. Порядок строк задаёт порядок событий,
даже если некоторые временные отметки совпадают.

## Проверка реализации

```bash
npm run check
npm run test:orchestrator
```

Тесты проверяют сохранение результата и порядок событий, изоляцию запусков,
ошибку исполнителя, пустую задачу, недоступное хранилище, справку и ошибки CLI.
Ветка `failed` проверяется подстановкой исполнителя, выбрасывающего исключение.

## Ограничения

Подключение модели, поиск, вызовы инструментов, повторные попытки,
таймауты, восстановление после прерывания и проверка JSX-примера не реализованы.
Журнал и состояние — отдельные записи, общей транзакции между ними нет.
При аварийном завершении они могут расходиться, а статус остаться `running`.
Возобновление прерванных запусков не поддерживается.
