# Учебный индексатор и UI Library Orchestrator

В проект добавлен шаг 2 оркестратора: запуск из терминала, состояния,
подготовленный ответ и журнал событий. Модель и поиск пока не подключены.

```bash
npm run orchestrate -- "Подбери кнопку для сохранения. Покажи загрузку и пример"
```

Команда компилирует TypeScript и запускает каркас. Результат находится в
`runs/<runId>/run.json`, события — в `runs/<runId>/events.jsonl`.
Папка `runs/` исключена из Git.

- [Шаг 1: сценарии и критерии](docs/orchestrator-step-1.md)
- [Шаг 2: устройство каркаса и практика](docs/orchestrator-step-2.md)

Проверка типов: `npm run check`. Проверки каркаса: `npm run test:orchestrator`.

## Шаг 6 предыдущего учебного плана: AI-дружественная документация

Этот мини-проект превращает публичный React-компонент `Button` в структурированный документ для будущего поиска и MCP-сервера.

## Что здесь происходит

Индексатор объединяет два вида знаний:

```text
TypeScript + AST + TypeChecker
        ↓ автоматические факты
props, типы, defaults, JSDoc, deprecated

docs/Button.docs.json
        ↓ курируемые знания
сценарии, ограничения, ключевые слова, примеры

        ↓ объединение и проверка
component-index.json
```

## Запуск

```bash
npm install
npm run extract
```

Команда сначала компилирует проект, затем запускает индексатор и создаёт `component-index.json`.

## Файлы для изучения

1. `src/ui/Button.types.ts` — prop API, наследование и JSDoc.
2. `src/ui/Button.tsx` — реализация и значения по умолчанию.
3. `src/ui/index.ts` — публичная граница пакета.
4. `docs/Button.docs.json` — смысловые правила и примеры.
5. `scripts/extract-component-props.ts` — индексатор.
6. `component-index.json` — AI-дружественный результат.

## Что находится в итоговом документе

- стабильный идентификатор с именем и версией пакета;
- правильный named import;
- компактная сигнатура;
- props, типы, обязательность и defaults;
- deprecated API;
- правила выбора и использования компонента;
- проверенные человеком примеры;
- ключевые слова для будущего поиска;
- ссылки на исходные файлы.

## Главная идея

Индексатор использует два источника знаний:

- `TypeChecker` раскрывает итоговый тип `ButtonProps`, включая унаследованный `id`;
- AST функции `Button` находит значения по умолчанию в деструктуризации.

Только AST увидел бы `ButtonProps` как ссылку на тип, но не обязательно раскрыл бы все его свойства. Только TypeChecker не сообщил бы, что `variant` по умолчанию равен `"primary"`.

Компилятор также не знает, что `danger` следует применять только для рискованных действий. Поэтому смысловые правила находятся в `Button.docs.json`.

```text
Код       → что технически разрешено
Docs      → когда и зачем это использовать
Генератор → объединить, проверить и нормализовать
```

## Этапы индексатора

### 1. Прочитать `tsconfig.json`

`readConfigFile` читает JSON, а `parseJsonConfigFileContent` вычисляет окончательный список файлов и compiler options.

### 2. Создать `Program`

`Program` представляет весь проект, а не один файл. Благодаря этому TypeScript разрешает импорты между `Button.tsx` и `Button.types.ts`.

### 3. Проверить diagnostics

При ошибках типов индексатор останавливается, чтобы не публиковать заведомо недостоверный индекс.

### 4. Получить публичные exports

Индексатор начинает с `src/ui/index.ts`, потому что внешний AI-агент должен видеть публичный API пакета, а не все внутренние объявления.

### 5. Разрешить alias

В `index.ts` компонент переэкспортируется. Symbol переэкспорта является alias, поэтому `getAliasedSymbol` приводит нас к настоящему объявлению функции в `Button.tsx`.

### 6. Получить call signature

Функциональный React-компонент с точки зрения TypeScript — вызываемое значение. Его call signature содержит параметры и возвращаемый тип.

### 7. Получить тип props

Первый параметр call signature — объект `ButtonProps`. `getPropertiesOfType` возвращает не только непосредственно записанные свойства, но и унаследованный `id`.

### 8. Обогатить свойства

Для каждого prop извлекаются:

- имя;
- итоговый тип;
- допустимые литеральные значения union-типа;
- обязательность;
- JSDoc;
- `@deprecated`;
- исходный файл объявления.

### 9. Найти defaults через AST

Индексатор находит первый параметр `Button`, проверяет `ObjectBindingPattern` и читает initializer каждого `BindingElement`.

### 10. Добавить сведения о пакете

Индексатор читает `name` и `version` из `package.json`, формирует стабильный `id` и правильный import.

### 11. Добавить курируемую документацию

`docs/Button.docs.json` проходит минимальную runtime-проверку. После этого правила, ключевые слова и примеры добавляются к автоматическим метаданным.

### 12. Создать компактную сигнатуру

Полный объект остаётся доступен программе, а `compactSignature` содержит короткую справку, которую удобно передавать LLM.

### 13. Нормализовать JSON

В `component-index.json` нет служебных AST-узлов. Там остаются только сведения, полезные MCP-серверу и AI-агенту.

## Ограничения текущей учебной версии

Индексатор намеренно поддерживает только один сценарий:

- именованный export `Button`;
- компонент как `function declaration`;
- props в первом параметре;
- литеральные defaults: строка, число, boolean или `null`.

Он пока не обрабатывает:

- arrow-компоненты;
- `memo` и `forwardRef`;
- несколько компонентов;
- discriminated unions без потери связей;
- вычисляемые defaults;
- примеры из Storybook;
- инкрементальное обновление индекса.

На этом этапе мы создаём качественную карточку одного компонента. Поиск, разбиение на chunks и MCP tools пока остаются следующими потребителями этой карточки.

Эти ограничения полезны: они показывают границу между учебным примером и промышленным индексатором.
