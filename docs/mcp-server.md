# MCP-сервер компонентов

Локальный MCP-сервер предоставляет поиск и документацию UI-компонентов
из `component-index.json`. Клиент получает API, правила использования,
примеры и источники через два инструмента: `searchComponents` и `getComponentDocs`.

Сервер работает как дочерний процесс Node.js. Сообщения JSON-RPC передаются
по `stdio`: запросы поступают через stdin сервера, ответы — через stdout.
Диагностика выводится в stderr.

## Быстрый запуск

Из корня репозитория:

```bash
npm ci
npm run extract
npm run mcp:demo -- "кнопка сохранения"
```

Демонстрационный клиент запускает сервер, получает список инструментов,
выполняет поиск, запрашивает документацию первого совпадения
и закрывает соединение. Для поиска подходят короткие запросы:
`Button`, `loading`, `кнопка сохранения`.

Оркестратор использует тот же сервер и сохраняет результат и журнал:

```bash
npm run orchestrate -- "Button"
```

## Подключение к MCP-клиенту

Перед подключением выполните `npm run extract`, чтобы собрать проект
и подготовить индекс. Для клиента с форматом конфигурации `mcpServers`
настройка выглядит так:

```json
{
  "mcpServers": {
    "ui-library": {
      "command": "node",
      "args": ["/absolute/path/ui-library-orchestrator/dist/src/mcp/cli.js"]
    }
  }
}
```

Замените путь на абсолютный путь к собранному серверу. В Windows допустим
вид `C:/projects/ui-library-orchestrator/dist/src/mcp/cli.js`.
Если Node.js недоступен через PATH клиента, укажите полный путь к исполняемому файлу.
Расположение конфигурации определяется выбранным MCP-клиентом.

По умолчанию сервер ищет индекс в корне проекта относительно собранного CLI.
Другой файл задаётся аргументом `--index`:

```bash
node dist/src/mcp/cli.js --index /absolute/path/component-index.json
```

Относительный путь `--index` разрешается относительно рабочей папки запуска.
При ручном запуске сервер ожидает сообщения MCP; завершить его можно через Ctrl+C.
Для обмена по протоколу stdout должен содержать только MCP-сообщения.

## Инструменты

### searchComponents

Находит компоненты по всем словам запроса.

```json
{ "query": "кнопка сохранения" }
```

`query` — обязательная строка длиной от 1 до 500 символов после удаления
крайних пробелов. Запрос должен содержать буквы или цифры.
Дополнительные поля отклоняются.

При сопоставлении применяется нормализация Unicode NFKC, нижний регистр
и замена `ё` на `е`. Каждое слово ищется как подстрока в имени компонента,
описании, ключевых словах, рекомендациях `whenToUse` и именах props.

| Поле ответа | Содержимое |
|---|---|
| `query` | Поисковый запрос |
| `total` | Количество совпадений |
| `components` | Карточки с `id`, `name`, `description`, `package` и `source` |

При отсутствии совпадений возвращаются `total: 0` и `components: []`.
Полный API компонента запрашивается через `getComponentDocs`.

### getComponentDocs

Возвращает документацию по точному имени компонента с нормализацией
Unicode, регистра, `е`/`ё` и удалением крайних пробелов.

```json
{ "name": "Button" }
```

`name` — обязательная строка длиной от 1 до 200 символов после удаления
крайних пробелов. Дополнительные поля отклоняются.

| Поле ответа | Содержимое |
|---|---|
| `found` | Признак найденного компонента |
| `name` | Запрошенное имя |
| `component` | Полная запись индекса или `null` |
| `message` | Пояснение к результату |
| `checks` | `{ "props": "not_run", "typescript": "not_run" }` |

Запись компонента включает сигнатуру, импорт, props, типы,
обязательность, значения по умолчанию, отметки устаревания,
правила использования, примеры, метаданные пакета и источники.

Примеры передаются из документации со статусами проверок `not_run`.
Оркестратор отдельно подготавливает и проверяет собственный TSX-пример;
его результаты находятся в файлах запуска, а не в ответе MCP-сервера.
Значения переменных состояния и обработчиков предоставляет использующее приложение.
При неизвестном имени возвращаются `found: false` и `component: null`.

## Формат ответов и ошибки

Успешный результат каждого инструмента представлен в `structuredContent`
и продублирован как JSON в текстовом блоке `content`.
Инструменты публикуют входную и выходную JSON Schema и аннотации операций чтения.

| Ситуация | Результат |
|---|---|
| Поиск без совпадений | Успешный ответ с пустым списком |
| Неизвестное имя компонента | Успешный ответ с `found: false` |
| Отсутствующий файл индекса | `isError: true` с рекомендацией выполнить `npm run extract` |
| Ошибка чтения, некорректный JSON или схема | `isError: true` с диагностикой |
| Неверные аргументы или неизвестный инструмент | Ошибка MCP SDK |

Клиент оркестратора проверяет структуру ответов по Zod-схемам
и передаёт ошибки исполнителю для записи в состояние запуска и журнал.

## Обновление данных

После изменения компонента, его типов, документации или метаданных пакета
выполните `npm run extract`. Сервер перечитывает индекс при каждом вызове,
поэтому обновлённые данные доступны в существующем соединении.

Дождитесь завершения генерации перед запросом. Если чтение произошло
во время записи файла и вернуло ошибку JSON, повторите запрос после генерации.

## Исходный код и проверка

Пути указаны относительно корня репозитория.

| Файл | Назначение |
|---|---|
| `src/components/schema.ts` | Схема записи компонента и TypeScript-типы |
| `src/components/catalog.ts` | Чтение индекса, поиск и получение документации |
| `src/mcp/server.ts` | Регистрация инструментов и обработка ошибок |
| `src/mcp/cli.ts` | Запуск сервера и выбор индекса |
| `src/mcp/client.ts` | Подключение оркестратора и проверка ответов |
| `src/mcp/contracts.ts` | Общие схемы результатов инструментов |
| `scripts/mcp-demo.ts` | Демонстрационный клиент |

```bash
npm run check
npm run test:mcp
```

Тесты запускают сервер отдельным процессом, проверяют инициализацию,
список инструментов, результаты вызовов, ошибки и обновление индекса.
