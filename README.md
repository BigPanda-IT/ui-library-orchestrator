# UI Library Orchestrator

CLI-инструмент для поиска компонентов React/TypeScript-библиотеки и получения
их API, правил использования и примеров через Model Context Protocol (MCP).
Проект объединяет индексатор исходного кода, локальный MCP-сервер
и оркестратор с сохранением результатов и журнала вызовов.

Оркестратор принимает поисковый запрос, получает документацию первого
совпадения и выводит props, версию пакета и пути к источникам. Для локального
`Button` он сохраняет TSX-пример и проверяет его props и типы.
Все операции выполняются локально; порядок вызовов задан кодом.
В репозитории в качестве исходного компонента используется `Button`.

## Быстрый старт

Проверенная среда: Node.js 20.20.0 и npm 10.8.2.
Выполните команды из корня проекта:

```bash
npm ci
npm run extract
npm run orchestrate -- "кнопка сохранения"
```

`extract` собирает проект и создаёт `component-index.json`.
`orchestrate` автоматически запускает MCP-сервер, выполняет запрос
и закрывает соединение после получения результата.

Передавайте короткий запрос одним аргументом в кавычках:

```bash
npm run orchestrate -- "Button"
npm run orchestrate -- "loading"
```

Выберите маршрут перед запросом:

```bash
npm run orchestrate -- --docs "Button"    # API и рекомендации
npm run orchestrate -- --example "Button" # API и проверенный пример
```

Без флага используется `--example`, как и в прежнем запуске. Маршрут задаётся
явно; программа не распознаёт намерение в произвольной фразе. Для `--docs`
пример не создаётся и проверки не запускаются. Маршрут сохраняется в `run.json`
и журнале событий.

Поиск сопоставляет все слова запроса с именем компонента, описанием,
ключевыми словами, назначением и именами props. Регистр букв не влияет на результат.

После изменения исходников, документации компонента или метаданных пакета
обновите индекс:

```bash
npm run extract
```

## Как устроен проект

```text
React/TypeScript + документация
            ↓ индексатор
    component-index.json
            ↓ MCP-сервер
    поиск → документация
            ↓ оркестратор
    --docs: API   |   --example: TSX → проверка и доработка
            ↓
    ответ в CLI + файлы + журнал
```

**Индексатор** анализирует публичный экспорт `Button` через TypeScript Compiler API.
Из кода извлекаются типы props, обязательность, значения по умолчанию,
JSDoc и отметки `deprecated`. Правила использования и примеры добавляются
из `docs/Button.docs.json`. Результат проверяется по общей Zod-схеме.

**MCP-сервер** предоставляет доступ к индексу по `stdio`.
При каждом вызове он перечитывает файл и проверяет структуру данных.

| Инструмент | Аргументы | Результат |
|---|---|---|
| `searchComponents` | `{ "query": "кнопка сохранения" }` | Краткие карточки найденных компонентов |
| `getComponentDocs` | `{ "name": "Button" }` | Props, типы, правила, примеры, метаданные пакета и источники |

**Оркестратор** управляет запуском: создаёт идентификатор, подключается к серверу,
вызывает поиск и запрашивает документацию первого совпадения.
Ответ формируется из полученных данных. Для `Button` код подготавливает
фиксированный сценарий сохранения с `loading`, `onClick` и обработкой ошибки.
Приложение передаёт в пример асинхронную функцию `onSave`.
Подготовщик формирует пример, проверяющий сравнивает props с API из MCP и
проверяет TypeScript по локальным исходникам. Оркестратор передаёт замечания
подготовщику и разрешает не более двух доработок.
Явное правило заменяет устаревший `isPending` на `loading`, если замена
однозначна; при других ошибках без правила цикл останавливается с причиной.
Имена инструментов, аргументы и исходы вызовов записываются в журнал.

## Результаты запуска

CLI выводит найденный компонент, его API, примеры и рекомендации,
а также идентификатор запуска и пути к сохранённым файлам.

| Файл | Содержимое |
|---|---|
| `runs/<runId>/run.json` | Запрос, статус, время выполнения и результат либо ошибка |
| `runs/<runId>/events.jsonl` | Журнал событий и вызовов MCP-инструментов |
| `runs/<runId>/example.tsx` | Пример использования локального Button |
| `runs/<runId>/tsconfig.json` | Настройки повторной проверки примера без генерации JS |
| `runs/<runId>/validation.json` | Статусы проверок и диагностика с кодами и строками |
| `runs/<runId>/attempts.json` | История вариантов, замечания, изменения и причина завершения |
| `runs/<runId>/example-<N>.tsx`, `tsconfig-<N>.json`, `validation-<N>.json` | Код и проверка отдельной попытки |

Успешный запуск получает статус `completed`. Если совпадений нет,
результат содержит `outcome: "not_found"`. Ошибка чтения индекса или вызова
инструмента переводит запуск в `failed`; CLI возвращает код завершения 1.
Ошибки в примере дают `validation_failed` и код 1; пример и диагностика сохраняются.
Устаревшие props дают предупреждения и требуют доработки. При отсутствии компонента файлы примера
не создаются, проверки остаются `not_run`.

Для демонстрации доработки запустите `npm run orchestrate:demo`: первый вариант
намеренно использует `isPending`, а после замечания проверяющего заменяется на
`loading` и проверяется повторно. Обычный запуск начинает с корректного примера.
Если исправление неоднозначно, результат повторяется или исчерпан лимит,
сохраняется последний проверенный вариант и статус `validation_failed`.

CLI выводит команду повторной проверки сохранённого файла:

```bash
npx tsc -p runs/<runId>/tsconfig.json
```

Проверяется подготовленный сценарий сохранения; текст запроса используется для
поиска и не меняет сценарий. Статическая проверка не запускает React-код
и не проверяет отображение. Исходные примеры документации сохраняются
в `result.component.examples` и отдельно не компилируются.

## Работа с MCP-сервером

Для проверки инструментов отдельным клиентом после генерации индекса:

```bash
npm run mcp:demo -- "кнопка сохранения"
```

Для подключения из другого MCP-клиента укажите команду `node`
и абсолютный путь к `dist/src/mcp/cli.js` в аргументах.
Сервер обменивается JSON-RPC-сообщениями через stdin/stdout.

При необходимости путь к индексу задаётся явно:

```bash
node dist/src/mcp/cli.js --index /absolute/path/component-index.json
```

Подробности подключения и форматы ответов — в [документации MCP-сервера](docs/mcp-server.md).

## Разработка и проверка

```bash
npm run build             # Сборка TypeScript в dist/
npm run check             # Проверка типов
npm test                  # Все тесты
npm run test:orchestrator # Тесты оркестратора
npm run test:mcp          # Тесты MCP-сервера
```

Интеграционные тесты запускают настоящий MCP-сервер и проверяют поиск,
получение документации, валидацию аргументов, обработку ошибок и сохранение
результатов. Тесты оркестратора также проверяют состояния и журнал запусков,
сохранение TSX, неизвестные и обязательные props, устаревшие параметры,
ошибки типов и повторную проверку артефакта обычным `tsc`.

## Структура репозитория

| Путь | Назначение |
|---|---|
| `src/ui/` | Исходный компонент, его props и публичные экспорты |
| `src/components/` | Схема индекса, чтение данных и поиск |
| `src/mcp/` | MCP-сервер, клиент и контракты инструментов |
| `src/orchestrator/` | CLI, исполнитель, управление запуском и хранилище |
| `scripts/` | Генерация индекса и демонстрационный MCP-клиент |
| `tests/` | Тесты оркестратора и MCP-сервера |
| `docs/` | Документация компонента и техническое описание проекта |

Подробнее об устройстве модулей и формате событий —
в [архитектуре оркестратора](docs/architecture.md).
