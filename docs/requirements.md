# Требования к UI Library Orchestrator

Документ описывает целевое поведение приложения. Текущая реализация
содержит индексатор и CLI с демонстрационным исполнителем;
модель, поиск и проверки примеров не подключены.

## Цель

Создать приложение, которое принимает вопрос об учебной UI-библиотеке,
находит сведения о компоненте и возвращает ответ на основе этих сведений.
Если пользователь просит пример, приложение готовит его и сообщает,
какие проверки фактически выполнены.

## Основной сценарий

Запрос: «Подбери кнопку для сохранения. Покажи состояние загрузки и пример».

Предполагаемый процесс:

1. Принять запрос и создать отдельный запуск задачи (`run`).
2. Найти подходящий публичный компонент в учебной библиотеке.
3. Получить его API, правила использования и источники.
4. Подготовить объяснение выбора и пример.
5. Проверить пример и указать выполненные проверки.
6. Вернуть результат и сохранить журнал действий.

Для базового сценария достаточно одного агента. Порядок выполнения
и ограничения контролирует код приложения.

## API исходной библиотеки

В публичной точке входа `src/ui/index.ts`
экспортирован один компонент — `Button`.

| Факт | Источник |
|---|---|
| Обязательный prop: `children: ReactNode` | `src/ui/Button.types.ts` |
| `variant`: `primary`, `secondary`, `danger` | `src/ui/Button.types.ts` |
| Необязательные props: `id`, `variant`, `loading`, `disabled`, `onClick`, `isPending` | `src/ui/Button.types.ts` |
| `isPending` помечен устаревшим; рекомендован `loading` | `src/ui/Button.types.ts`, `docs/Button.docs.json` |
| По умолчанию: `variant="primary"`, `loading=false`, `disabled=false` | `src/ui/Button.tsx` |
| При `loading=true` кнопка заблокирована и показывает «Загрузка…» | `src/ui/Button.tsx` |
| Внутренний HTML-элемент имеет `type="button"`; публичного prop `type` нет | `src/ui/Button.tsx`, `src/ui/Button.types.ts` |
| Props `size` нет | `src/ui/Button.types.ts` |
| `danger` предназначен для рискованных действий | `docs/Button.docs.json` |
| Имя учебного пакета: `ast-component-indexer-learning`, версия: `1.0.0` | `package.json` |

Индекс должен соответствовать текущим исходникам. Пересборка выполняется
командой `npm run extract`; версия пакета не заменяет проверку актуальности индекса.

Типы определяют допустимый API, реализация — фактическое поведение,
курируемая документация — рекомендации. При противоречии источников
приложение должно показать несоответствие. Например, `isPending` объявлен
в типах, но текущая реализация его не использует; обещать включение
загрузки через этот prop нельзя.

## Контрольные запросы

Сценарии определяют целевое поведение и не покрываются текущими тестами каркаса.

| ID | Запрос | Ожидаемый результат | Недопустимое поведение |
|---|---|---|---|
| S1 | Подбери кнопку для сохранения, покажи загрузку и пример | Выбран `Button`, объяснены `loading` и блокировка; пример содержит `children`, `onClick`, `loading`; указаны источники | Выдуманные props или утверждение, что пример проверен, без запуска проверки |
| S2 | Найди DatePicker для выбора даты | Сообщение, что `DatePicker` не найден в текущей учебной библиотеке; пример для него отсутствует | Выдуманный компонент, его импорт или API; утверждение, что DatePicker вообще нигде не существует |
| S3 | Покажи Button с size="large" | Сообщение, что `size` отсутствует в API; предложен базовый пример без `size` с объяснением ограничения | Молчаливое удаление требования или выдача `size` как поддерживаемого prop |
| S4 | Покажи загрузку через isPending | Предупреждение об устаревшем prop, пример с `loading`; объяснено, что реализация не использует `isPending` | Использование `isPending` в рекомендуемом примере |
| S5 | Сделай Button с type="submit" для нативной отправки формы | Объяснение, что публичного `type` нет, а внутри задан `type="button"`; требование не выполнено текущим API | Пример с неподдерживаемым `type` или обещание нативной отправки формы |

S1–S3 — базовые сценарии. S4–S5 проверяют учёт ограничений библиотеки.

## Пример ожидаемого ответа для S1

«Подходит `Button`: компонент запускает действие через `onClick`.
Передайте `loading=true` на время операции: кнопка блокируется и показывает
текст загрузки. Для обычного сохранения подходит вариант `primary`».

Фрагмент JSX:

```tsx
<Button loading={isSaving} onClick={saveDocument}>
  Сохранить
</Button>
```

`Button` должен быть импортирован из библиотеки. `isSaving` и `saveDocument`
предоставляет код приложения; фрагмент сам не реализует сохранение
и не переключает состояние. Для проверки TypeScript требуется
окружение с импортом и объявлениями этих значений.

Источники ответа: `src/ui/Button.types.ts`, `src/ui/Button.tsx`,
`docs/Button.docs.json`. Источник метаданных пакета — `package.json`.

## Требования к результату

- Идентификатор запуска и его статус.
- Ответ по исходному запросу и выбранный компонент, если он найден.
- Источники фактов и известную версию учебного пакета.
- Пример, если он уместен, с пояснением необходимых внешних переменных.
- Предупреждения о неизвестных или устаревших props и отсутствующих данных.
- Результат проверки: `not_run`, `passed` или `failed`, с названием
  реально выполненной проверки. Проверка props и компиляция TypeScript
  должны учитываться отдельно.
- Путь к сохранённому журналу выполнения.

Статус запуска описывает выполнение программы. «Компонент не найден»
может быть корректным результатом завершённого запуска. Ошибка чтения
индекса — техническая ошибка, а не доказательство отсутствия компонента.

## Требования к базовому сценарию

Терминальный интерфейс, TypeScript/Node.js, один агент, локальный индекс,
инструменты `searchComponents` и `getComponentDocs`, сохранённый журнал
и ограничение числа обращений к модели. Поставщик модели не определён.

Критерии приёмки:

- S1–S3 дают ожидаемые ответы на данных библиотеки.
- Журнал показывает обращения к модели, вызовы инструментов и причину остановки.
- Неизвестный инструмент и неверные аргументы не запускают произвольное действие.
- Техническая ошибка явно отражается в результате запуска.
- Лимит шагов останавливает цикл с отдельной причиной завершения.
- До реализации проверки примеров их статус — `not_run`.

Редактирование исходников библиотеки, произвольные команды, веб-интерфейс
и визуальный редактор процессов находятся за пределами базового сценария.
