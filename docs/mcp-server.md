# Локальный MCP-сервер компонентов

## Где остановились и что добавлено

Шаги 1–2 дали требования, CLI оркестратора, состояния запусков и журнал.
Подключение модели на шаге 3 было отменено и удалено. Текущий этап —
MCP-сервер, который предоставляет реальные данные учебной UI-библиотеки.

```text
Демонстрационный MCP-клиент (scripts/mcp-demo.ts)
    ↓ initialize → tools/list → tools/call
Локальный сервер (отдельный процесс Node.js, stdio)
    ↓ чтение и проверка схемы
component-index.json
    ↑ npm run extract
Исходники Button + docs/Button.docs.json + package.json
```

Сервер не обращается к модели и не генерирует ответы. Код клиента задаёт
последовательность: поиск → документация первого совпадения.
Существующая команда `npm run orchestrate` всё ещё использует `mockExecutor`.
Интеграция MCP-вызовов в этот исполнитель и его журнал — отдельный следующий этап.

## Быстрый запуск

Из корня проекта:

```powershell
npm ci
npm run extract
npm run mcp:demo -- "кнопка сохранения"
```

Клиент выводит имена двух инструментов, результат поиска и документацию `Button`.
Он сам запускает и останавливает сервер. Дополнительный терминал не нужен.

Пример отсутствующего компонента:

```powershell
npm run mcp:demo -- "DatePicker"
```

Результат — пустой список совпадений. Это успешный поиск, а не техническая ошибка.
Вводите короткие поисковые слова. Например, `Button`, `loading`, `кнопка сохранения`.
Сервер не интерпретирует свободную речь и не понимает запрос «подбери мне…» как инструкцию.

## Подключение MCP-клиента

Перед подключением выполните `npm run extract`: команда собирает TypeScript
и формирует индекс. Затем клиент должен запускать **непосредственно Node.js**:

```json
{
  "mcpServers": {
    "ui-library": {
      "command": "node",
      "args": [
        "C:/Users/lena_/OneDrive/Documents/ChatGPT/Агентская разработка/dist/src/mcp/cli.js"
      ]
    }
  }
}
```

Это пример для клиентов с форматом `mcpServers`; расположение настройки зависит
от клиента. Для другого расположения проекта замените абсолютный путь.
Если `node` отсутствует в PATH клиента, укажите абсолютный путь к `node.exe`.

По умолчанию индекс ищется рядом с корнем проекта относительно собранного CLI,
поэтому рабочая папка клиента может быть любой. Другой индекс задаётся при старте:

```powershell
node dist/src/mcp/cli.js --index "C:/path/to/component-index.json"
```

Относительный `--index` разрешается относительно рабочей папки запуска.
Аргументы инструментов не позволяют менять путь к файлу или запускать команды.

`stdio` означает обмен JSON-RPC через stdin/stdout дочернего процесса.
Сервер не открывает HTTP-порт. Это стандартный локальный транспорт
[MCP TypeScript SDK](https://ts.sdk.modelcontextprotocol.io/server.html#stdio).
В проекте зафиксированы `@modelcontextprotocol/sdk@1.26.0` (ветка v1 с CommonJS)
и `zod@4.3.6`; версия SDK не является версией протокола MCP.

При ручном запуске сервер молча ожидает сообщения MCP. Для завершения — Ctrl+C.
stdout зарезервирован под протокол, диагностика CLI идёт в stderr.
Для ручного запуска через npm есть `npm run --silent mcp:start`;
в настройках MCP-клиента предпочтителен прямой запуск `node`, без служебного вывода npm.

## Инструменты

### searchComponents

Вход:

```json
{ "query": "кнопка сохранения" }
```

Обязательная строка до 500 символов после удаления пробелов по краям.
Пустой запрос или запрос только из знаков пунктуации отклоняется.
Поиск не учитывает регистр и различие `е`/`ё`; каждое слово должно встретиться
как подстрока в имени, описании, keywords, whenToUse или именах props.
Склонения, синонимы и семантический поиск не реализованы.
Ограничения и отрицательные рекомендации не используются для поиска:
упоминание отсутствующего `size` в ограничении не делает его доступным prop.

Выход: `query`, `total`, `components`. Карточка содержит `id`, `name`,
`description`, `package` и `source`. Полные props и примеры запрашиваются отдельно.

### getComponentDocs

Вход:

```json
{ "name": "Button" }
```

Обязательная строка до 200 символов. Сравнение точное, без учёта регистра
и крайних пробелов. Дополнительные аргументы обоих инструментов запрещены.

Выход:

- `found` — найден ли компонент;
- `component` — полная запись индекса или `null`;
- `name` и `message` — запрошенное имя и пояснение;
- `checks` — `props: "not_run"`, `typescript: "not_run"`.

В записи компонента есть сигнатура, импорт, типы и обязательность props,
значения по умолчанию, deprecated, правила, ограничения, примеры и источники.
Проверка структуры JSON выполняется, но она не является проверкой JSX-примеров.
Примеры взяты из документации; переменные обработчиков и состояния предоставляет
использующее приложение. Имя пакета в импорте — метаданные учебной библиотеки,
а не утверждение о публикации пакета в npm.

Успешные ответы доступны и как `structuredContent`, и как JSON в текстовом
`content`. Оба инструмента публикуют входную и выходную JSON Schema,
а также аннотации операций только для чтения.

## Ошибки и актуальность

Отсутствующий компонент возвращает `found: false`, `component: null`.
Отсутствующий файл, ошибка чтения, некорректный JSON или неподдерживаемая схема
возвращаются с `isError: true`; данных об успешном поиске в таком ответе нет.
MCP SDK отклоняет неверные аргументы и неизвестные инструменты.

Индекс читается заново при каждом вызове: после исправления файла или
перегенерации серверу не нужен перезапуск. Каждый вызов использует один снимок
файла. Сам сервер не сравнивает индекс с исходниками: после изменения TSX,
типов, package.json или документации нужно снова выполнить `npm run extract`.
При чтении в момент незавершённой записи возможна ошибка JSON; повторите вызов
после окончания генерации. Автоматических повторов нет.

## Файлы и проверки

| Файл | Назначение |
|---|---|
| `src/components/schema.ts` | Единая Zod-схема и TypeScript-типы для генератора и сервера |
| `src/components/catalog.ts` | Чтение, валидация индекса, поиск и документация |
| `src/mcp/server.ts` | MCP-инструменты и формат результатов |
| `src/mcp/cli.ts` | Путь индекса и stdio-транспорт |
| `scripts/mcp-demo.ts` | Демонстрационный MCP-клиент |
| `tests/mcp.test.cjs` | Интеграционные тесты с реальным дочерним сервером |

```powershell
npm run check
npm test
```

Тесты MCP генерируют индекс из реальных исходников, проверяют handshake,
обнаружение инструментов, результаты поиска и документации, неизвестные имена,
ошибочные аргументы, повреждение/удаление индекса и восстановление без перезапуска.
Сервер запускается из другой рабочей папки, чтобы проверить разрешение пути.
Также проверяется отсутствие постороннего текста в stdout.

Текущий индекс содержит один компонент `Button`. Поддержка каталога из нескольких
компонентов, resources/prompts, централизованные правила и CI/CD не входят в этот этап.
